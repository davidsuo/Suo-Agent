# AI Native 开发契约 v1.0

> 生效日期：2026-09-27
> 适用范围：本仓库所有代码改动

---

## 第一条 · 契约精神

> **改代码前跑一次回归。改完代码再跑一次。全绿才算改完。**

---

## 第二条 · 三条铁律

### 铁律 1：本地绿、云端绿，代码才可合并

- 任一环境红 → **不允许** merge 到 `main`
- **不允许**"先合并，回头修"

### 铁律 2：不跳过、不忽略、不注释掉失败的测试

- 用例失败先问"系统错了还是脚本错了"
- **断言过时 → 改断言，不删断言**

### 铁律 3：改完必须 commit + push，代码才算"改完"

- `git status` 必须 clean
- **磁盘绿 ≠ 云端绿**

---

## 第三条 · 提交前必跑清单

```bash
python rag_test/regression/run_all.py           # 本地回归（23 用例）
python rag_test/regression/run_all.py --cloud   # 云端回归
git status                                       # 工作区必须干净

三项全绿，才允许 commit。
```
---

## 第四条 · 每次改动的三个动作
1. 改前：跑一次，记录基线
2. 改后：再跑一次，对比结果
3. 全绿：才允许 commit

---

## 第五条 · 例外处理
| 场景	        | 规则
| 紧急 hotfix	| 允许跳过云端验证，commit message 必须标 [HOTFIX]，24 小时内补跑
| 探索性改动	| 允许在 feature 分支上不跑，合并前必须补齐
| 文档改动	    | 允许跳过回归，但 commit message 必须标 [DOC]

---

## 第七条 · 违规处理
1. 违反上述契约的 commit：
2. 立即 git revert
3. 打 tag violation/YYYY-MM-DD-<reason>
4. 复盘并更新本文档
